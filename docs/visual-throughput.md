# 视觉导出调度

## 0.42.0：普通快照合并与跨配方编码重叠

普通 Job 进度/客户端观察仍实时更新内存，但文件快照按单调时钟合并至 250 ms 间隔；阶段或操作 phase 变化立即保存，启动、取消、终态及来源/分片/诊断报告保持原来的即时保存行为。失败的强制写入不会丢失待保存意图。没有新计时器或后台服务，空闲时由下一次更新或生命周期边界保存待写内容。

每条配方的所有原生截图仍在游戏线程顺序完成。之后以保留引用对应关系的 JSON 副本隔离记录与视图，像素和记录依次进入原有单工作线程队列；下一条原生捕获可以与前一条 PNG 编码重叠。记录提交在其全部资产提交之后，所有队列提交仍由导出线程执行，不在 PNG 工作线程访问原生对象或写 Rows。

例外是 `Picture` 类型的共享布局/轨迹目标：例如 GT 的 `Ui.layouts` 缓存会把同一个背景元素交给下一条配方，必须先完成当前图片的资产 ID 写入。因此含 Picture 的批次先排空编码，再复制记录。模型与非配方调用保留同步行为；每个处理器结束前排空队列，才关闭原生处理器或封卷。失败或取消依然不能发布不完整 Source。

队列仍限制 8 项和 16 MiB 权重，权重同时计入图片像素及 JSON 节点、字符串、晚到 ID 的估计成本。该值是限流估算，不是 JVM 实际堆占用的精确测量。单个超限批次先排空队列再同步处理；不会累积无界数量的待写配方。PNG 缓存上限保持不变。

定向回归使用真实 Job 文件证明快照节流、边界、内存观察、失败写入重试和取消落盘；使用真实 Sink/Pipeline 延迟编码，证明下一条可以继续，嵌套 JSON/图标/视图不串数据、共享背景 ID 已就绪、失败不提交后续记录。现有队列背压检查、Source/Jobs、离屏 GL 继续验证。真实速度和资源余量仍需外部实机验收。

本轮仅做一次固定 0.40.1 基准与 0.42.0 候选的熔炉/粉碎机 A/B，测量累计优化效果；不额外重跑 0.41.0 或旧版全量。0.41.0 在没有新实机回执前仍为本地验证通过、实机未执行。

## 0.41.0：已纳入的批量截图与编码复用

0.40.0 的一次失败 Core 导出运行 18,752.994 秒，记录 344,014 次客户端交接，累计排队 15,803.109 秒、客户端执行 187.956 秒。PNG 编码 222,663 次，累计 560.993 秒；资产写入计时累计 1,806.747 秒。各计时可能重叠，不能相加当作独占墙钟，也不能把这次中断运行称为完整 210 项基准。

## 实现

- 配方事实与首批图片共享一次客户端调用。后续图片复用现有 `Slice` 的 32 操作、4 ms、4 MiB 协作式边界，在操作之间让出线程。单张图片的原生绘制、帧复制和像素转换不可抢占，可能超过一个边界；4 ms 不是硬性最大回调时间。模型采集保留原路径。
- 每批图片先在客户端取得独立像素，再交给既有后台 PNG 队列。当前配方的所有图片、编码与记录提交完成后才推进原生游标；原生背景及动态图片不会因为缓存命中而跳过捕获。队列维持原有 8 项 / 16 MiB 限制，超限单图先排空队列后处理。
- PNG 缓存仅保存编码字节，限 2,048 项 / 16 MiB。键包含宽、高及全部 ARGB 像素（包括透明像素的 RGB）；非默认 ARGB 颜色模型保留原编码路径。缓存属于一次导出，无跨会话复用。SHA256 与既有内容寻址使用同一碰撞假设。
- 最近 8,192 个相同资产 ID 不重复提交资产行。每次仍构建含来源、尺寸、时间线的独立身份；像素相同而来源或动画不同的资产仍保留。磁盘文件去重及失败发布规则不变。

## 验证与测量

`visualThroughputTest` 是独立小型行为检查，覆盖 PNG 原始字节、子图、颜色模型、透明 RGB、缓存预算、顺序和原生游标所有权；还调用真实 Sink 核对内容 ID、来源与动画独立性。`glTest` 的现有离屏 OpenGL 检查增加连续批次颜色验证，保留物品本体和覆盖条检查。原生 sludge/oil 与既有 Source/Jobs 构建检查继续执行，不增加大型回归框架。

Job performance 增加 `pngFingerprint`、`pngReuse`、`assetRowReuse`。`pngEncode.calls` 表示实际编码次数；`pngEncode.calls + pngReuse.calls` 表示图片编码请求总量，包含非 ARGB 绕过。保留 `clientQueue`、`clientRun`、`assetWrite` 的 `calls` / `micros`；最大客户端回调应从 operation 或诊断 timings 的 `maxMicros` 读取，若未采集则如实注明。不要将嵌套计时相加。

该轮原定使用 0.40.1 与 0.41.0 做同一熔炉/粉碎机 A/B，尚未收到实机回执。本轮按上文改测最终候选。版本变化会改变环境及 Source ID，跨版本应核对语义、数量、实际像素及动画差异原因；每一份 Source 自身的直出/组装路径仍要求字节一致。随后只对新候选执行原定四项 Pilot 和 210 项验收，不重复旧版全量。

本轮不实现断点续写、跨配方并行或跨环境缓存。失败 `writing` 分片不能组装或借用为新 Source；真实性和像素验收门禁保持有效。
