# Native batch fixes (0.45.0-semantic.10)

Pair this candidate with Compiler 0.40.0-semantic.8 and contracts 0.40.0-semantic.74.
Source/Catalog remain revision 40. This is a new candidate; historical live checks
are not reused across versions or sessions.

The current batch separates raw owned content from executable metadata predicates,
admits exact Forge readonly ore-list backing and Forestry Hashtable storage, and
binds infusion membership per relevant item instead of retaining the global ore
table. NotEnoughIDs harvest map/default semantics and Hodgepodge smelting maps
retain their actual native lookup priorities. Structure health checks run on the
client thread. MCP/SRG aliases remain explicit.

Dedicated native callback models cover the observed ForbiddenMagic orb, GT/BW
containers, Railcraft bucket, EnderCore maximum, HarvestCraft garden, GT loot,
Witchery name hashing, Chisel and Scala mutation-description boundaries.
Botania MiniFlower predicates and named-head dynamic output/priority are typed;
the latter binds its real current-locale default name as a Text observation.
Squeezer callback programs distinguish verified no-container rules from finite
GT fluid tables, preserving drain targets, raw short metadata and original NBT.

Zero-cost incubator inputs still require the exact fluid/NBT object. Trade
quantity observations may contain zero. A loaded missing player scan list is
the native empty query. Creative/void cell wrappers with no ICellInventory are
captured as an explicit cellFault observation, never as an empty cell or a
successful content list. Native faults and local test results are not game-wide
acceptance. Source export still requires fresh full diagnostic gates.

Every serialized exception node now carries Java's native fatal classification,
including bounded omitted nodes. Missing severity still stops the Bridge. IO,
Error, cleanup, cancellation, environment drift and suppressed cleanup failures
remain unsafe; this change does not downgrade them.

NBT admission recognizes the exact Hodgepodge 2.6.112 Object2ObjectOpenHashMap
backing with a null default value, alongside vanilla HashMap. Unknown subclasses,
foreign callbacks and NBT budget violations remain rejected. Smoker auto-add
resolves the healing callback on ItemFood, its actual declaring base class.

BuildCraft subtype capture recognizes closed read-only getter bodies: constants,
boolean fields, primitive integer comparisons and validated item delegation.
Unknown bodies, side effects, synchronization and dependency cycles are rejected
before invoking their callbacks. No package-wide callback allowance is introduced.

The installed NEICustomDiagram 1.7.5 EnderStorage overviews register global and
personal actions only. Capture no longer invents the newer refresh action pair.

Firework rules follow the actual single registered vanilla or Et Futurum rule.
Each probe creates an owned instance. The fixed rule produces three rockets,
always records Flight, and omits an empty Explosions list. It does not mutate the
registered recipe instance or substitute vanilla examples.

TGreg raw tool-part templates are preserved, including absent material NBT. A
display which needs that tag is selected from the completed native inventory
catalogue with the same item/metadata and otherwise identical NBT. The reference
records an explicit tgregInventory displayBinding with the native material name
and version. Unknown, absent or ambiguous variants fail; the original template is
not rewritten and tooltip listeners are not disabled. Display-source drift stops
the run. Compiler and Web validate the same narrow binding.

Local native fixtures and contract checks do not establish whole-pack acceptance.

The next batch shares each private Binnie source domain once. Recipe capture
retains the exact member/conversion witnesses used by that row, detaching them
before publication; the Database keeps the full gene catalogue. It does not
parse a full multi-megabyte catalogue for every rule. Matching conversion
selectors retain their original priority. Gendustry interns identical owned
stack witnesses and charges its retained 32 MiB budget to unique facts, with
separate bounded rule edges. Counts, native NBT and drift checks remain intact.

The target crop plugin deduplicates crafting and usage tables separately. Its
matches() groups by result, points and parent count, ignoring the parent vector
and denominator. Capture preserves the union and explicit craftingListed /
usageListedFor provenance, while retaining each observed points/total without
renormalization. It validates complete coarse memberships and seals both actual
tables; it does not run the predictor or infer missing combinations.

The intentionally malformed firework probe is recorded as typed raw input state
inside failure.inputs. It never becomes a display Item fact or invokes the
native tooltip/render pipeline. Other exceptions still propagate. Compiler and
Web replay the raw state only inside the bounded rule evaluator.
The external Agent must run a fresh complete data/content diagnostic batch in
each language. All failures, blocked sources and unchecked ranges remain visible;
this batch still does not publish Source or run the full export.
