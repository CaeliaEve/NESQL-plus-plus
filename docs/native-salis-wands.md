# Salis wand replacements

Batch status: implementation only, not compiled or validated. No game acceptance, candidate, or export readiness is implied.

The adapter targets Salis Arcana 1.1.33-GTNH and GTNH-TC-Wands 1.4.6. It binds the actual rod/cap registries, Salis item/metadata mappings and diagnostic sentinels, ordered GTNH wrappers, wrapper costs, conductors and screw membership, primal aspects, relevant research keys and configuration dependency chains. Casting bracelets also bind their actual metadata-indexed arrays and special ThaumicBases roles. Borrowed NEI and ordinary arcane output specimens remain source-bound until sealing.

Only the known base component getters and pinned wand subclasses are admitted. Unknown getter overrides, shadow fields, collection implementations or metadata callbacks require a specific adapter. The adapter reads config enabled/dependency/mod-load values directly. Calling the native optional-mod `isEnabled` path could populate its lazy `loadState`, so result/cost extraction does not call it or native replacement result methods.

The result projection follows the pinned source order on owned stacks: copy, set rod/cap, clear Vis or clamp preserved rod Vis, then set item damage to `max(crafting cost, 0)`. Preserved charge capacity is observed before resetting metadata. This matters for casting bracelets, whose effective rod, cap and capacity depend on metadata even when component NBT has been written. The `salisWand` result edit distinguishes this from the generic metadata-preserving `patch` edit. Wrapper integer operations and sceptre float-to-int conversion retain Java behavior.

The current `salisReplacement` process records first-nine-cell roles, literal component metadata, the actual screw/conductor rule, signed native cost, the pre-metadata charge capacity and the separate post-metadata result capacity. The item/meta component lookup precedes wand classification; conductor item/meta comparison precedes screw ore membership. All screw candidates share a cross-item exclusion rule, covering every mapped rod and wand item within that ore domain. Null mapping values are unmapped. A mapped wand item is a component in that branch, not automatically forbidden. A stack of caps cannot replace multiple occupied cap cells. Other occupied cells reject a match.

`32767` in Salis' component map is a literal key. The replacement path does not feed it through the ore-wildcard expander. An unrenderable literal specimen must fail explicitly; it is not a proof that the component is unreachable. UNKNOWN component/research registrations are retained rather than discarded based on an obtainability assumption. Native staff-rod assignment replaces `AttributeModifiers`; the generated list and its attribute/UUID dependencies are bound separately.

Compiler and Web require the typed process for a `salisWand` edit; a display property cannot confer these semantics. Repeated roles share their exact choice domain. The finite matcher counts occupied cells, rejects extras, and ignores cells after nine. Broad ore and ignored-NBT alternatives are deduplicated during role matching. Candidate changes hide an output that no longer satisfies the inventory rule. Materials and output descriptions remain conditional, with separate Chinese and English text.

Original source/result samples do not claim that Minecraft's world, research or payment path ran. Optional self-payment requires the loaded Salis workbench mixin, no prior normal result, an empty supply slot and an eligible non-staff input. It pays using OLD components and player discounts. Preservation then clamps the post-payment charges to the RESULT capacity; that is distinct from the earlier replacement clamp. Configuration alone is not mixin-execution proof. The generated-contract version boundary, installed parity and concentrated lightweight verification remain release gates for this batch.
