# Gendustry owned source context

2026-10-22 implementation update; not yet compiled, tested or accepted in the unified batch.

`GendustryAlleles` admits the installed Forestry, Binnie, MagicBees, Gendustry and GT accessor owners before calling UID, dominance, species-root or integer-value methods. Enum naming, identity/hash, tree plant-type and diagnostic text callbacks are included. Observed UID, dominance, root, integer and plant-type values are checked at sealing. The instance-owned class admission and observation caches have explicit count/text budgets and are released on close. Static class-file census is supporting source review, not evidence that every runtime allele or Handler passed.

Native `Tree` construction mutates the EnumSet returned by `AllelePlantType.getPlantTypes()`. The shared `ForestryMembers` therefore supplies an owned plant-type allele with a cloned set and the same native UID/localization fields. It does not modify the registered allele. The known native factory still constructs the individual; a foreign result class is rejected before later callbacks. The default form group preserves the original order and the queen conversion's mutation of that owned individual. Independent analyzed previews do not reuse the same live individual across forms.

The same ownership boundary covers tree NBT readers in the GT scanner/tree farm and Binnie/Forestry specimens. Native `TreeGenome` first reads an owned NBT copy, preserving its repair/error rules and primary/secondary order. Before `Tree.setGenome` runs, each parsed genome receives owned chromosome objects and plant-type sets. Main and mate genomes preserve shared allele identity within that member, without sharing writable sets with the registry. The native tree constructor, analysis bit and mate serialization remain in use. Root selection keeps the pinned registry's first matching root order. This is production implementation pending the unified local verification batch; it is not evidence of game execution or complete genetics callback coverage.

`GendustrySpecimens` shares one reader-owned root/default/template context between process metadata and catalogue generation. Identical genotype/form/replication-mode requests reuse owned stack specimens. Root and sample budgets are cumulative. At sealing a fresh context and catalogue are reconstructed, and their semantic fingerprints are compared. Fast batch checks do not rebuild the full catalogue.

`GendustrySamplerSource` reads native sorted samples and explicit chromosome associations without invoking the map's default function. It binds sample-info, root, chromosome, allele, species-set and species identities. The installed stateless missing-key function is admitted by its exact native owner. Replacing an info object with an equal-content object is still a source change.

`GendustryConfiguration` reads initialized lazy scalar fields directly. For a cold field it projects the installed getter from the ready bdlib ConfigSection, without invoking a lazy getter or setting its bitmap. The pinned bitmap masks were checked with static javap of the installed 1.9.4 JAR. Float narrowing, round-to-long then narrow-to-int, native truth sets and US lowercase semantics are preserved. A null required tuning section is not-ready, not a default configuration.

`GendustryMutationSettings` reads a ready override map only after admitting its constant-default definition. If the cache is cold, it projects the API table and tuning override merge, retaining native string filtering, invalid-setting omission, precedence and ENABLED default. It does not invoke Scala Map.apply/default, initialize the native lazy cache or emit the native logger's side effects. The source/cache path and resulting settings are bound and checked when sealing.

The six genetics readers, template reader and two fluid readers use these paths. Recipe/tooltips retain their conditional genome, world, RNG, energy and output-space rules; these code changes do not claim a game execution or export result. Actual native factory parity, source replacement, cancellation/close, Scala/config edges, transport identity and budget checks remain in the single final verification queue. Existing proxy-based tests need migration to the tightened production boundaries; historical fixtures and receipts are not rewritten to manufacture success.
