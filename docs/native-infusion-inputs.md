# TC4Tweaks infusion inputs and inheritance

Status: unverified implementation batch. This is source/bytecode analysis, not native execution evidence. The final contract generation, lightweight tests and candidate build have not run.

`InfusionInputSource` now accepts the exact native TC4Tweaks enhanced definition, reading `central` and `components` directly. Item/OR/ore/strict-ore/error predicates have explicit raw field shapes and native concrete content examples. It does not call `InfusionRecipeExt.convert`, whose native implementation fills a loading cache. Missing ore names are read without registering new names. Unknown callbacks/backing implementations remain errors.

Correction from the continuing source/bytecode review: the conversion API's ore-mode **ingredient factory** is not the base recipe's execution predicate. Ordinary `InfusionRecipe.matches` uses the static offered-first comparison, wildcard substitution and a no-extra-pedestal check. Native TC4Tweaks `EnhancedInfusionRecipe.matches` uses its ingredient predicates and permits leftovers. Ordinary definitions and admitted dynamic subclasses use `NativeInfusionRecipes` / `InfusionLegacyInputs`; exact TC4Tweaks Enhanced now uses that same typed process with a separate `startup: enhanced` predicate graph. The old generic display-conversion fallback in `MagicRecipes` has been removed. Unknown subclasses require a dedicated execution reader.

Deferred ingredients are not executed as arbitrary method handles. The JDK8 adapter creates two owned `Utility.convertUnderCurrentRule` probes, checks their bound-handle class, normalized LambdaForm, method type and all captured fields, then identifies the single stack argument. The native deferred handle must match that same factory structure except for this stack. Only its bound template is read. A read-only projection interprets the current source-bound mode; it does not call `mode.get` or execute the supplier. None/default/relaxed factory predicates differ from the cycle comparator. Strict retains its original-target exact-NBT singleton branches, exclusive-ore branch and ordered literal intersection. The native empty-intersection branch can clear a borrowed ore group; that branch is reported as `native_factory_mutation` instead of executing it or inventing a successful pure result. A changed supplier, another capture or an unknown/customized form outside this proof is rejected before invocation. This proof remains to be exercised in the concentrated verification round; it does not extend support to arbitrary suppliers or JVMs.

Enhanced startup and cycle requirements remain independent. Startup performs declaration-order greedy predicate matching and accepts leftovers. The altar's inherited `getComponents` returns its constructor-time `ItemStack[]`, not the subclass's current ingredient list. Later consumption uses that saved array and the configured cycle comparator, without the startup wildcard rewrite. Source/Rust/TS retain both phases; raw wildcard templates have no icon/name facts. The current unverified stock projection first tries the ordered startup specimens. If they do not also satisfy the cycle, it appends complete ordered cycle-only specimen groups. Each phase keeps its own greedy assignment and allows the other phase's unused stock. Startup and constructor cardinalities may differ; the old equal-cardinality guard and exponential minimal-tuple search are removed. Displayed groups are physical stock specimens, not extra fixed costs. Peripheral consumption is conditional `allocated`: used slots are replaced whole, unused stock remains, and a container is returned only for a selected pedestal. Both phases must pass for the first displayed tuple; changing choices can hide an invalid result. Missing safe specimens or transport-budget exhaustion are faults, not unreachable-recipe exclusions. Native copy/NBT observations, installed parity and concentrated verification are still required.

`InfusionInheritance` binds the configuration and actual merger instance/captured whitelist. It admits that closure by comparison with the pinned pure `mergeNBT(Set)` factory. Thus a stale merger is interpreted using its actual captured keys, rather than guessing them from newer configuration values. Per-recipe custom override detection traverses the pinned JDK WeakHashMap storage without invoking map get/iteration, which can expunge stale entries. No native ClassValue behavior cache is populated.

The adapter copies only owned output stacks, reproduces root-only key filtering, compound recursion and same-element-type list append, and retains destination scalars. The native filtered-merge/null-output-tag failure is not turned into an invented successful output. Base Item and Forge ItemTool classification have independent source bindings. The installed TConstruct HarvestTool tool-class getter is independent of NBT/Broken; those checks belong to its harvest-level getter. CoFH, admitted constant owners and EnderIO's spoon-aware predicate have explicit projections. Stateful BloodMagic/AmunRa queries now have owned effects, nested capacity dependencies and the new nativeInfusionMerge contract; see native-infusion-tool-effects.md. The continuing unverified batch also includes golem, old/new familiar, revolver, GTNHLib pedestal replacements, armor disguise and Machina augmentation. Runic provider observations and the independent four-mode nativeRunic process have been written; installed-provider/native-query parity and complete conditional payment remain audit work. This input/inheritance module alone does not close that scope.
