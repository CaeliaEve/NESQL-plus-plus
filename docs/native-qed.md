# QED semantic reader

The pinned ExtraUtilities 1.2.12 manager exposes one ArrayList shared by shaped
and shapeless recipes. Its NEI page enumerates shaped recipes; every earlier
shapeless definition still participates in first-match selection. A finished
craft resets the native 20,000 Ender Flux buffer and decrements every occupied
input cell by one without any container callback. Supply/space conditions make
elapsed time variable. The reader preserves the existing typed QED process.

The production cursor opens the native reader before the NEI factory. No native
cache, logical-position projection, GUI geometry or PositionedStack is created.
Raw definitions reuse the audited vanilla/Forge family parser after rejecting
foreign recipe/stack/list and metadata owners. Binding covers actual static
table identity, all selected/unselected order, input/alternative/stack/item/tag
instances, raw counts/NBT, fixed output and native flags. Initial missing and
ready-empty are distinct. Capture checks before and after; sealing checks the
entire registry. Close releases owned copies and never clears the borrowed
registry/cache. All four registrations bind the same actual static source.

Finite wildcard examples use the shared NativeItemVariants reader, which binds
finished native item-map roots/members/facts without GUI or item callbacks.
Templates retain their native NBT as offered examples while the matching rule
explicitly ignores it. Unknown container behavior does not become a false QED
gate: this machine never calls it. Unknown metadata/matching behavior does.

ShapedRecipes with the native copy-NBT flag reuse the linear LAST-tagged-cell
projections. The actual manager calls getCraftingResult, so the flag cannot be
treated as inert or replaced by a fixed result. `qed.copyNbt: true` is emitted
only for this branch; ordinary rows omit it. The output action retains the base
and complete candidate projections. Offered physical order, translation and
mirroring determine the last tagged cell; the entire compound replaces the
base's compound. These are projections of the native rule, not a claim that a
one-cell inventory satisfies the whole recipe.

The existing native QED runner uses owned managers/tables, restores its Loader,
locale and static roots, and compares native ordinary/mirrored/tag-transfer
behavior. It is local conformance, not live full-pack or pixel acceptance.
