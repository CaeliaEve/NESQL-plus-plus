# NESQL++

从 **GT New Horizons 2.8.4 Java 8** 的本机单人世界采集游戏事实、纹理和配方视图，发布不可变的 Elysium source 数据集。游戏内 `/nesql` 与本地 MCP 使用同一个任务服务。

旧 SQL/JPA、Protobuf、standalone exporter、旧格式转换和兼容入口已移除。发布物只有一个模组 jar，以及单独运行的 Node MCP 桥接程序。

## 当前能力

- NEI 物品顺序、折叠分组、矿辞、完整 typed NBT、提示文本和流体属性。
- 原版工作台与熔炉；GT 默认处理器及已核对的 BartWorks BioLab/BioVat 处理器。
- TCNEIAdditions 1.5.4 的有序/无序奥术、坩埚和注魔适配：从注册配方读取基础 Vis/源质、研究条件、不稳定性及中心材料；原生处理器仅接收副本，用于取得位置与背景。TC4Tweaks 1.5.39 的矿辞、唯一矿辞、NBT 匹配、组合输入和产物 NBT 继承均显式记录。
- 候选输入、精确数量、非消耗输入、工具损耗/容器归还、GT 概率和类型化配方元数据。
- 图标、平面 sprite 动画、NEI 配方图层，以及原版熔炉和已核实 GT 布局的进度动画。静态图层复用，裁剪轨迹单独按内容保存；渲染在游戏线程执行，编码、排序和写盘在后台执行。
- 单任务执行、持久幂等键、取消、重开界面恢复观察、分页查询已完成的导出。
- GT 注册材料的成分、可用部件、准确含量及流体形态；直接读取目标 NEICustomDiagram 1.7.5 定义的电路系列、电路板、配件与电压等级。
- Forestry 4.10.17 的蜜蜂/树木默认基因、实际物品形态、产物与突变登记。蜜蜂基础产率和突变百分比统一为精确分数；树木可能产物保留未知概率。

- StructureLib 1.4.23 的结构片段，以及独立预览世界中的整体构建结果。游戏界面和 MCP 可指定 1–16 组数量/通道参数，各组独立构建并保留结果或明确失败原因。保存实际方块、完整方块实体 NBT、控制器坐标与原生返回值；几何按 2048 格分块。使用 BlockRenderer6343 1.3.17 的基础世界和独立玩家，在副本对象上调用原生构建，不写玩家世界。
- Thaumcraft 4.2.3.5 的要素组成、物品要素、研究前置关系与触发线索；保留快照中的知识状态和原生图标。未同步知识明确为未知，采集不执行扫描或解锁。

尚未完成全量 GTNH 处理器覆盖、多方块完整装配、魔法配方与完整研究页面的迁移。材料、电路、遗传、结构片段、要素及研究关系已有新记录与前端展示，实际游戏采集仍待验收；不表示 NEICustomDiagram 的全部交互图都已迁移。未知配方处理器会明确失败；选择已支持的处理器会生成标记为 `selection` 的数据集，不会伪装成完整导出。OC Pattern 和样板导出不在本次范围内。

## 构建

需要 Java 8 **JDK**（设置 `JAVA_HOME`）和 Node 22 以上。依赖版本以 `gradle.properties` 与 `build.gradle.kts` 为准，不从其他游戏实例自动猜测。

```powershell
# 首次准备 Forge 工作区时执行一次
.\gradlew.bat setupCIWorkspace --no-daemon

.\gradlew.bat build --no-daemon
node scripts/check-jar.mjs
npm --prefix bridge ci
npm --prefix bridge test
node scripts/release.mjs
```

普通增量构建无需重复 setup 或 clean。`build` 执行两组 Java 行为检查并生成经过 reobf 的 `build/libs/NESQL++-0.10.6.jar`。`check-jar` 检查实际产物的命令和预览世界 SRG 方法、版本替换和打包边界。`release` 要求目标目录不存在，按明确清单打包，不操作游戏目录。

可用 `NESQL_LOCAL_MAVEN_REPO` 指定本地 Maven 仓库。Forge 1.7.10 的工具链固定为 ForgeGradle 1.2.11 / Gradle 6.9.1；这里的旧版本是目标游戏的构建约束。

## 在本机使用

目标实例是 `E:\GTNH\.minecraft\versions\GT New Horizons 2.8.4-java8`。发布包内的 `mod` 目录仅包含新的模组；安装时应停游戏并移走旧 NESQL 模组和旧 deps 包，避免两个入口同时加载。仓库不再提供自动删除或自动部署脚本。

桥接程序在游戏之外运行。先在其 `bridge` 目录执行 `npm ci --omit=dev`，然后为所用的 MCP 客户端配置一个 stdio 服务：

```json
{
  "command": "node",
  "args": [
    "E:/path/to/nesql/bridge/src/index.mjs",
    "--instance",
    "E:/GTNH/.minecraft/versions/GT New Horizons 2.8.4-java8"
  ]
}
```

`--instance` 必须是明确的绝对目录。加载单人世界后，先用 `inspect_game` 确认 NEI 就绪、处理器覆盖、来源和研究注册表检查通过，再用 `start_export` 提交任务。没有 Agent 时也可执行 `/nesql`。

跨项目的安装、导出交接和真实数据验证入口见 [真实游戏验收](acceptance/README.md)。脚本支持分别指定 NESQL、Compiler 和 NeoNEI 发布包，保留每次导出的原始记录与验收结果。

| profile | 内容 |
| --- | --- |
| `full` | 物品、流体、配方、分组、材料、电路、遗传、文本、纹理和配方视图 |
| `data` | 游戏事实、材料、电路、遗传与配方，不捕获纹理或视图 |
| `images` | 物品、流体、分组、材料、电路、遗传和图标，不枚举配方 |

`full` 且没有指定处理器子集时才申请完整快照；其他请求明确记录选择范围。一次导出产生 `nesql/datasets/<内容 ID>/manifest.json` 及其声明的文件。编译器负责完整语义和文件校验，NeoNEI 只读取编译后的 catalog。

## 验证状态

source/catalog 修订为 10。匹配规则属于每个输入候选；网格形状独立于截图保存，研究观察状态不进入配方内容 ID。构建变体与环境中的请求参数逐项对应。TCWands 的普通法杖组合从最终 ShapedArcaneRecipe 注册表读取；Salis 换芯/换端按部件、形态与配置惰性枚举，保留原生 NBT 变换、独立材料槽位与自行供能条件。施法手环和一次性法杖按目标子类的实际语义处理。未知 IArcaneRecipe、未核实的配方覆写和自定义 NBT 函数仍明确失败。

注魔的 Object[]{标签名, NBT} 输出保存为根标签替换；TC4Tweaks 的默认继承保存为 merge 操作，包含模板、根键白名单与护甲/工具限制。每个中心候选都有通过原生函数在副本上取得的产物示例。示例不进入配方语义 ID，编译器仍逐项验证其 NBT、metadata、数量和引用。目标版本“非空白名单且模板无 NBT”的错误分支会明确拒绝，不伪造成功结果。

整体预览按请求的每组数量/通道参数独立构建，控制器朝南。原生生存建造分轮执行，预算 256、上限 8192 轮；单个第三方回调仍不可抢占。新建世界、玩家、控制器和供应物品均独立管理；异常和取消也清理世界并恢复原线程更新标志。

外观采集使用目标 GTNHLib 0.7.10 的四边形采集器。已接入原版世界方块、GT 方块/外壳及已核实的 GT 世界渲染回调，保留实际顶点、UV、顶点颜色、固体/透明通道和纹理。相同方块状态可因位置和邻接产生不同模型；方块计数仍按状态统计。data profile 明确省略外观，full/images 尝试采集。普通/陷阱箱、双箱和末影箱的专用实体模型已接入；其余专用实体、其他模组渲染器和未核实的机器覆写目前明确报告不支持，完整快照拒绝缺失外观；这些适配和真实游戏验证仍需继续。

GT 的统一方块实体入口仅在 MTE 实现 IMTERenderer 时绘制附加几何，普通机器继续采集世界模型。激光板保存板体和双面透明光束，采集读取原生偏移量、姿态和颜色，不推进原生计时器；未知实体实现仍明确失败。

动态视图使用 `clip` 元素引用共享 `tracks`。GT 默认、净水、装配线、太空装配、太空项目与研究站的已核实工厂使用独立窗口、物品栏和注入时钟，保存普通/分段/环形填充的原生像素步进。图层按原生顺序排列，文字覆盖层独立保存；太空项目纹理按当前配方读取，绘制后恢复共享字段。原版熔炉保留其 48 tick 箭头与火焰周期。轨迹只代表界面演示，不能作为实际机器进度；未知工厂、嵌套进度或控件覆写会报告 `view_unsupported`，其他自定义交互仍需继续适配。

Java source/jobs 行为检查、真实本机 HTTP 端点、MCP SDK stdio 握手/工具调用、生产 jar 校验已通过。尚未在运行中的 GTNH 世界部署验证；不能据此宣称 GL 兼容性、全量性能或所有领域已经验收。
